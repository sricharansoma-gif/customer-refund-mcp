# Customer Refund MCP Server

A TypeScript MCP server that exposes customer lookup and mock refund tools using the official Model Context Protocol SDK.

## Tools

### `get_customer_record`

Retrieves a mock customer record.

Input:

```json
{
  "customer_id": "CUST-12345"
}
```

Validation:

- `customer_id` must use the exact format `CUST-XXXXX`.
- Each `X` must be a digit.
- The prefix is case-sensitive.

### `trigger_refund`

Creates a mock refund result for an existing customer.

Input:

```json
{
  "customer_id": "CUST-12345",
  "amount": 25.5,
  "reason": "Customer was charged twice"
}
```

Validation:

- `customer_id` must use the format `CUST-XXXXX`.
- `amount` must be a positive number.
- `reason` is trimmed before validation.
- `reason` must contain between 10 and 500 characters.

This project does not connect to a real customer database or payment provider.

- `data.ts` contains synthetic customer records.
- `schemas.ts` defines the Zod input-validation schemas.

## Installation

Clone or download the project, enter its directory and install the locked dependencies:

```bash
npm install
```

## Development

Run the TypeScript source directly:

```bash
npm run dev
```

The server uses stdio and waits for an MCP client. Stop it with `Control + C`.

## Build

Compile TypeScript into JavaScript:

```bash
npm run build
```

Compiled files are written to `dist/`.

## Start

Build the project and run the compiled server:

```bash
npm run build
npm start
```
## Automated Tests

Run the validation test suite:

```bash
npm test
```

The automated tests cover:

- Correctly formatted customer IDs
- Malformed customer IDs
- Valid refund requests
- Zero and negative refund amounts
- Short and whitespace-only reasons
- Trimming surrounding whitespace
- Reasons longer than 500 characters

A successful run should report seven passing tests and zero failures.

## Validation and Error Handling

Zod validates all incoming tool arguments before tool handlers execute.

A malformed input, such as `CUST-1234`, is rejected by the MCP SDK during input validation.

A correctly formatted but nonexistent customer, such as `CUST-99999`, reaches the handler and produces a structured business error marked with `isError: true`.

## STDIO Safety

The server uses the MCP stdio transport:

- `stdin` receives MCP requests.
- `stdout` is reserved exclusively for MCP JSON-RPC messages.
- `stderr` receives application and diagnostic logs.

The server uses `console.error()` for logs and does not use `console.log()`, preventing accidental corruption of the protocol stream.

## Security Notes

This is a local demonstration project:

- Customer records are synthetic.
- Refunds are simulated.
- No real money is moved.
- No database or payment provider is connected.
- No public HTTP endpoint is created.
- No credentials are required.

A production implementation would additionally require authentication, authorization, idempotency, refund limits, transaction persistence, audit logging, secret management and payment-provider integration.
